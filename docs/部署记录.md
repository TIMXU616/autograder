## 部署约定

1. **只从仓库出包**：暂存目录由仓库 `backend/` + 仓库 `templates/grading/` 生成，不允许从别处改完直接部署。
2. 部署包**不含** `.env`、`autograder.db`、`backend/uploads/`、`backend/tests/`。
3. 服务监听平台注入的 `PORT` 并绑定 `0.0.0.0`；入口 `run_server.py` 先 `init_db()` 与进程内 seed，再起 uvicorn。
4. 部署版不带 key，评分走 mock（每项固定 80%）。**正式对外的版本必须带 key 跑真评分**，这一条在 9/24 上线前处理。
5. 每次部署后跑一遍冒烟：拉模板 → 上传 → 触发 → 轮询到终态 → 成绩列表，结果记进上表。
6. **发布包的制作方式**（B 于 9/23 补，此前只在口头，导致 18:35 那次事故）：暂存目录需含
   ① `backend/`（排除 `.venv`、`__pycache__`、`*.db`、`uploads/`、`tests/`、`data/`）；
   ② `templates/grading/`；③ 前端构建产物放 **`frontend/web/`**（不要放 `frontend/dist/` ——
   发布平台会过滤 build output 目录名，`run_server.py` 因此按 `dist → web → backend/static`
   顺序探测）；④ `backend/.env`（key 留空即 mock）。
   启动命令 `python backend/run_server.py`，安装命令 `pip install -r backend/requirements.txt`。
   **`run_server.py` 必须入库**（9/23 前它只存在于暂存目录，是「只从仓库出包」落不了地的根因）。
