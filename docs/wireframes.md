## 0. 全局信息

### 0.1 路由表

| 路由 | 页面 | 对应文件 |
|---|---|---|
| `/upload` | 上传报告页（首页） | `src/views/UploadView.vue` |
| `/result/:id` | 评阅结果页 | `src/views/ResultView.vue` |
| `/reports` | 成绩管理页 | `src/views/ReportsView.vue` |
| `/templates` | 评分模板页 | `src/views/TemplatesView.vue` |

页面流转：`上传页` →（提交评阅，轮询完成）→ `评阅结果页` →（返回）→ `成绩管理页` →（查看详情）→ `评阅结果页`；`评分模板页` →（用此模板评阅）→ `上传页`。

### 0.2 三态通用规范

| 状态 | 呈现方式 | 组件 |
|---|---|---|
| 加载态 | 页面级用骨架屏，表格/下拉用局部 loading | `el-skeleton` / `v-loading` / `:loading` |
| 空态 | 居中插画 + 一句说明 +（可选）行动按钮 | `el-empty` / 表格 `empty-text` |
| 错误态 | 页面级用空态位 + 重新加载按钮；操作级用红色浮层提示 | `el-empty` + 按钮 / `ElMessage.error` |

### 0.3 得分率色带（统一语义）

| 得分率 | 颜色 | 语义 |
|---|---|---|
| ≥ 85% | 绿（success） | 优秀 |
| 70–84% | 蓝（primary） | 良好 |
| 60–69% | 橙（warning） | 及格 |
| < 60% | 红（danger） | 不及格 |

> 注：成绩管理页目前只用了 3 档（≥85 绿 / ≥60 蓝 / 其余橙），P2 会统一为 4 档，与结果页一致。

### 1.2 交互流程

1. 进入页面即请求 ⑤ 预载模板列表，默认选中第 1 个
2. 用户选模板 → 展开显示评分点（元素 5）
3. 拖入/选择文件 → 前端立即校验扩展名与大小（≤20MB），不合法则提示并清空
4. 点「提交评阅」→ 调 ①，拿到 `report_id` 后**每 1.5 秒轮询 ②**
5. ② 返回 `done` → 提示「评阅完成」→ 跳转 `/result/{report_id}`
6. ② 返回 `failed` → 提示「评阅失败，请检查报告内容后重试」

## 2. 评阅结果页 `/result/:id` ⭐ 重点页面

> **设计要点（任务卡强调）**：必须把「**逐项核查 + 原文依据**」做成**一等公民展示**，不能只丢一个总分——这是**技术创新性 30% 的主证据**。
> 因此本页的信息层级是：**逐项核查表（核心）> 总分与得分率 > 总评与建议**，逐项表占据页面主视觉，且每行同时给出「得分 / 得分率进度条 / 判定依据 / 依据出处」四项。

### 2.1 页面元素清单

| # | 元素 | 类型 | 说明 | 数据来源接口 |
|---|---|---|---|---|
| 1 | 「返回成绩列表」按钮 | 文本按钮 | 跳 `/reports` | — |
| 2 | 页标题「评阅结果」 | 文本 | 固定 | — |
| 3 | 报告元信息行 | 文本 | 文件名 · 学生 · 模板名 · 评阅时间 | **③ GET /reports/{id}/result** |
| 4 | 总分大字 | 文本 | `total_score / full_score`，按得分率着色 | ③ |
| 5 | 得分率仪表盘 | `el-progress`（dashboard） | 132px 环形，按得分率着色 | ③（前端计算） |
| 6 | 卡片「评分点逐项核查」 | 容器 | **本页核心** | — |
| 7 | 逐项核查表 | `el-table` | 列：评分点 / 得分 / 得分率进度条 / 判定依据 / 依据出处 | ③ `items[]` |
| 8 | 卡片「总评与建议」 | 容器 | — | — |
| 9 | 总评正文 | 文本 | — | ③ `comment` |
| 10 | 亮点列表 | 图标 + 列表 | 绿色勾图标 | ③ `highlights[]` |
| 11 | 改进建议列表 | 图标 + 列表 | 星形图标 | ③ `suggestions[]` |

**逐项核查表列定义（核心交付）**

| 列 | 字段 | 宽度 | 说明 |
|---|---|---|---|
| 评分点 | `items[].name` | 190 | 如「算法设计与实现」 |
| 得分 | `items[].score` / `items[].full_score` | 110 | 得分加粗，满分灰字 |
| 得分率 | 前端由 `score/full_score` 计算 | 160 | 条形进度条，按色带着色 |
| 判定依据 | `items[].reason` | min 260 | AI 的判定理由 |
| 依据出处 | `items[].evidence` | 180 | 原文位置，如「代码块 L20-L80」 |

### 2.2 三态

| 状态 | 触发条件 | 界面表现 | 现状 |
|---|---|---|---|
| 加载态 | 进入页面请求 ③ | 骨架屏 8 行（`el-skeleton` animated） | ✅ 已实现 |
| 空态 | `:id` 对应的报告不存在或尚无评阅结果 | 空态位 + 「未找到该报告的评阅结果」+ 返回列表按钮 | ⚠️ 待补：目前直接显示后端错误文案，需区分「不存在」与「网络错误」两种空态 |
| 空态 | `items` 为空数组 | 表格显示「暂无评分点数据」 | ⚠️ 待补 |
| 错误态 | ③ 接口失败 / 超时 | 空态位显示 message + **「重新加载」按钮**（重新调 ③） | ✅ 已实现 |
| 错误态 | 报告仍在评阅中（`status != done`） | 提示「评阅进行中」并自动轮询 ② | ⚠️ 待补：直接访问 `/result/:id` 时的兜底 |
