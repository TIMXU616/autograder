## 三、交接给 LearnBuddy 的任务（按优先级）

### P0 · 今天必须开始

1. **设计评分点模板**（作品核心）
   - 目标：针对计算机专业实验报告，设计 2 套模板（建议《数据结构》《计算机网络》）
   - 每套 5–8 个评分点、总分 100，每点须有**可核查**的判定标准（不能是"写得好"这类无法判定的表述）
2. **设计评分 Prompt 并产出可运行的后端评分服务**
   - 输入：报告纯文本 + 评分点模板
   - 输出：**严格结构化 JSON**（`total_score` / `comment` / `highlights` / `suggestions` / `items[]{name, score, full_score, reason, evidence}`）
   - 硬约束：`reason` 必须基于报告真实内容、`evidence` 必须指向具体位置、各评分点得分之和等于总分
   - 交付形态：**可直接运行的 FastAPI 代码**（含报告解析：`python-docx` / `pdfplumber`）

### P1 · 明天前

3. **数据库表结构 + 建表脚本**（SQLite，三张表起步）
4. **补齐 5 个接口的后端实现**，使前端能关掉 Mock 联调
   - ① `POST /reports` 上传并触发评阅
   - ② `GET /reports/{id}/status` 查询评阅状态（`processing` / `done` / `failed`）
   - ③ `GET /reports/{id}/result` 获取评阅结果
   - ④ `GET /reports` 成绩列表（支持 `keyword` / `template_id` / 分页）
   - ⑤ `GET /templates` 评分模板列表
5. **回答前端提出的 8 条接口确认项**（`docs/wireframes.md` 第 5 节 Q1–Q8），其中 Q2（筛选参数用 `template_id`）与 Q3（结果接口补 `student`、`created_at`）会直接导致联调返工，优先

### P2 · 有余力再做

6. 部署方案（单机托管：前端静态文件 + FastAPI uvicorn）
7. 报告素材处理脚本（批量解析 docx/pdf 为纯文本，供 C 的测试集使用）
