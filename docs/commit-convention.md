# 提交信息规范

工程完整性占总分 25%，评委可能查看提交历史，因此每次提交的信息必须能看懂"改了什么、为什么改"。

## 格式

```
<type>: <简短中文描述>
```

## type 取值（只用这 6 个）

| type | 含义 | 示例 |
|---|---|---|
| feat | 新增功能 | `feat: 完成报告上传页拖拽上传与格式校验` |
| fix | 修复缺陷 | `fix: 修复评分结果页刷新后总分丢失的问题` |
| docs | 文档变更 | `docs: 补充接口文档中评阅结果字段说明` |
| refactor | 重构（不改功能） | `refactor: 抽取评分点表格为独立组件` |
| test | 测试相关 | `test: 补充空报告与乱码报告的边界用例` |
| chore | 杂项（配置、依赖） | `chore: 配置 vite 开发代理指向本地 8000 端口` |

## 要求

1. **一句话说清做了什么**，描述部分用中文，不超过 30 字
2. **一次提交只做一件事**，不要把"改接口 + 调样式 + 加依赖"混在一个提交里
3. **禁止** `update` / `修改` / `111` / `。` 这类无意义信息
4. 提交前确认 `.env`、数据库文件、`node_modules` 没有被 `git add` 进来

## 分支约定

- `main`：随时可运行的主干，只在功能验证通过后合并
- `dev`：日常开发分支
- 合并 `main` 前在群里说明，避免多人同时改动冲突
