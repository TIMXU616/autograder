# 后端缺陷修复（P0 两条 + P1 一条 + P2 三条）

真机验证结果：用真实 GLM key 在 glm-4.7 上跑了三个用例，主链路是通的（case_good 100 分、七项全 graded、evidence 全部命中原文、总分等于各项之和、comment 与 highlights 与 suggestions 正常落库）。但下面这些必须修。

只改指定位置，不要重写整份文件，不要动已通过的解析层错误码（4001/4004/4005）、重试参数、并发信号量、时间戳写法。

## P0-1 跑题护栏在真模型上失效（违反验收标准）

**实测证据**：`case_offtopic.docx`（食堂调研，与数据结构实验无关）跑出 `total_score=13.2`、`status=success`，其中第 6 项给了 5.7 分、第 7 项给了 7.5 分。同一个提示词在对话层测是 0 分，换到 glm-4.7 就变成 13.2 分——模型不可靠，护栏必须由后端兜底。

**修法（两层都做）**：

1. 提示词层：在 `backend/app/prompts/scoring_v1.md` 的护栏 2 里，把跑题时写入 warnings 的文案固定下来，要求 warnings 的**第一条**必须是这个固定串：`报告内容与数据结构实验无关`。不许换词。
2. 后端层（决定性，不能只靠提示词）：在 `app/services/grader.py` 的 `_normalize` 里加跑题兜底。判定条件：warnings 中任意一条包含下列任一关键词——`无关`、`跑题`、`不是数据结构`、`与数据结构实验无关`。命中后强制执行：
   - 所有 items：`score = 0.0`、`level = "absent"`、`status = "graded"`、`confidence = "high"`、`evidence = null`
   - `total_score = 0.0`
   - warnings 保留并追加固定串 `报告内容与数据结构实验无关`
   - 同时写一条日志
3. 补一个 pytest 用例：喂一份假的模型响应（items 里有非零分 + warnings 里带「无关」），断言所有项被清零、total_score 为 0。

**验收**：重跑 `case_offtopic.docx`，total_score 必须是 0.0，七项全部 absent，warnings 含固定串。

## P0-2 reports 表缺 student 列，两个接口拿不到该字段

**实测证据**：`reports` 表当前列是 `['report_id','template_id','filename','file_sha256','status','uploaded_at']`，没有 student。而契约 5.4 GradingResult 与 5.5 GradeListItem 都已含 `student | string | null`，语义是「后端取上传文件名去掉扩展名作为初值，未取到为 null，模型不输出该字段」。现在 B 的结果页与成绩列表都拿不到。

**修法**：

1. `app/repositories/db.py`：`reports` 建表语句加 `student TEXT`；并按已有 comment / highlights / suggestions 的写法，加一段 `ALTER TABLE reports ADD COLUMN student TEXT`，包在 try 里吞掉「列已存在」的异常，兼容老库。
2. `app/repositories/grading_repo.py`：
   - `insert_report` 增加 `student` 参数并写库。
   - `get_result` 返回体里带上 student（结果表里没有这列，需要按 report_id 从 reports 表取）。
   - `list_grades` 的 SELECT 增加 `p.student`，返回项里带上。
3. 上传入口处计算 student：取 filename 去掉最后一个扩展名，去首尾空格；为空则 None。上传接口本身的请求字段不变，仍是 file + template_id。

**验收**：重跑一次端到端，`GET /result` 与 `GET /grades` 的返回里都能看到 student 且值与文件名一致；`insert_report` 不再漏列。

## P1-3 docx 解析无异常兜底，且无正文时不报 4003

**问题**：`_parse_docx` 没有 try/except。损坏的 docx（坏 zip）会抛 `zipfile.BadZipFile` 直接冒到顶层变成 500，违反「解析层任何情况不许裸抛 500」。另外纯图片的 docx（抽不出文字）会返回空文本继续进评分流程，而契约语义是这类应报 4003。

**修法**：

1. `_parse_docx` 包 try/except：异常信息含 `encrypted` / `password` → 抛 4005；其余异常 → 抛 4003。
2. docx 抽出的文本去空白后少于 50 字（复用 `PDF_MIN_CHARS` 这个阈值）→ 抛 4003，与 pdf 的处理保持一致。
3. 补两个 pytest 用例：损坏的 docx（随便写几个字节的假文件）、纯图片无文字的 docx（用 python-docx 建一个只有图片不吃文本的，或用假文本长度触发），断言分别抛 4003。

## P2-4 三条小问题（P0、P1 修完再顺手处理）

1. `score` 有时是整数（`0`、`15`），契约要求 1 位小数。在 `_normalize` 里对每个 `score` 做 `round(float(x), 1)`，None 保持 None。
2. `llm_client._mock_chat` 只返回三个顶层键，缺 comment / highlights / suggestions。mock 也要返回六键（comment 给一句占位中文、两个数组给空数组），否则没配 key 时端到端测不出这三个字段。
3. `_retry_timeout` 里如果重试时返回 429 或 5xx，会直接落到 5001/5002，不再走过载退避。把这两类响应交回过载重试路径处理。
