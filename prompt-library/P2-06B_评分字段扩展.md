# 评分提示词字段扩展（scoring_v1.md 修订）

契约刚追认了结果页需要的四个字段：student、comment、highlights、suggestions。其中 student 由后端从上传文件名派生，不进提示词；另外三个必须由模型输出，所以要改 `backend/app/prompts/scoring_v1.md`。

只改下面指定的位置，其余内容一字不动。不要重写整份文件，不要改调用参数、三版温度、超长策略和十个 items 字段的定义。

## 改动一：顶层键由三个变六个

把 system 里**所有**「顶层只有三个键」这类表述改成「顶层只有六个键」，并给出新结构：

```json
{"items": [], "total_score": 0.0, "comment": "", "highlights": [], "suggestions": [], "warnings": []}
```

改动点在 system 的【输出格式】段、以及 user 模板末尾那句「顶层只有 items、total_score、warnings 三个键」。全文凡涉及顶层键数量的地方都要改到，改完自查一遍，不许残留「三个键」字样。

## 改动二：新增三个字段的定义

在 system 的字段表里补三行：

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| comment | string | 总评，中文一段 80 到 150 字，说清整体水平、主要优点与主要问题；不得逐条复述 items 的 reason；未出分时为空字符串 |
| highlights | array\<string\> | 亮点，0 到 4 条，每条一句，每条必须能在报告原文里找到依据；没有就空数组 |
| suggestions | array\<string\> | 改进建议，0 到 4 条，每条一句且可执行，写「做什么」而不是「要注意什么」；没有就空数组 |

同时把【禁止输出】那段里的字段清单更新：模型禁止输出的仍然只有 report_id、template_id、filename、student、顶层 status、attempt_no、model、consistency、error_code、时间戳这几项，comment、highlights、suggestions 由模型输出。

## 改动三：护栏联动（只动这几处，其余护栏一字不改）

在护栏 2（跑题）后面补一句处置：comment 写明「报告内容与数据结构实验无关」，highlights 为空数组，suggestions 给 1 条「按数据结构实验要求重写报告」。

在系统规则里「确实找不到依据的评分项」那条后面补一句：comment 照常给出并说明哪些部分缺失，不得因为缺依据就把 comment 留空。

在护栏 6（某项调用失败）后面补一句：comment 里注明「第 N 项评分失败，总评不含该项」。

## 改动四：字段对齐表补一段

在第四节字段对齐表下方补一段说明：模型输出的 comment、highlights、suggestions 由后端填入 GradingResult 的对应字段；student 由后端取上传文件名去扩展名派生，模型不得输出；GradingResult 的其余字段仍由后端填充。

## 改动五：追加两例复跑

用 `case_good` 与 `case_offtopic` 各跑一次改后的提示词，把原始输出**追加**到 `docs/试跑记录_P1-05_prompt_v1.md` 末尾新开的一节「字段扩展复跑」里，逐条记录：

1. 顶层是否恰好六个键。
2. comment 是否非空，字数是否落在 80 到 150 之间。
3. highlights 与 suggestions 是否为数组，不是字符串。
4. case_offtopic 的 comment 是否写明跑题、highlights 是否为空数组。
5. total_score 是否仍等于各项 score 之和。
6. json.loads 是否成功。

## 自检

1. 全文再无「三个键」「三个顶层键」这类残留表述。
2. 三个新字段的定义与 `docs/接口契约.md` 第 5.4 节一致：comment 80 到 150 字，highlights 与 suggestions 各 0 到 4 条。
3. 调用参数、三版 temperature、超长分段策略、十个 items 字段定义均未被改动。
4. 两例复跑结果已追加进试跑记录，能看到原始输出。
5. student 没有被写进 system 或 user 的输出要求里。
