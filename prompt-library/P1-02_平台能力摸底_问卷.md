# 平台能力问卷

回答下面的平台能力问题。这份问卷的答案会直接决定我们后端的超时、重试、并发参数和加分档取舍，数字错了会连带返工，所以按下面的规矩答。

## 背景

我们在做一个 FastAPI 后端的实验报告评阅工具：后端解析 docx / pdf 全文后调大模型，按评分点逐项输出结构化 JSON。你答的这些边界决定我们敢不敢这么设计。

## 回答规矩

1. 每个问题必须落在三种状态之一：
   - 已知：给出明确答案，注明依据（官方文档、产品界面、实测结果）。没有依据的不算已知。
   - 待验证：写【待验证】，并附一条可执行的验证方法。
   - 无法得知：写【无法得知】，说明卡在哪。
2. 禁止推测。禁止用"一般来说""通常""大概"起句。禁止编造具体数字。
3. 输出为 Markdown 表格，五列：编号、问题、答案、依据或验证方法、状态。
4. 表格之外只写一段不超过 100 字的总结：哪些项待验证，按对项目的影响从大到小排。

## 问题

1. 对外 API：平台有没有可供我方后端代码调用的 API（OpenAI 兼容接口或 SDK）？怎么申请凭证？如果没有 API，模型调用是不是只能发生在平台对话里？
2. 可用模型：你当前对话背后跑的是哪个模型（准确标识或版本号）？如果可选，有哪些可选？
3. 输入上限：单次请求能接收的最大输入是多少（字数或 Token）？超限是截断还是报错？
4. 输出上限：单次最大输出多少字？
5. JSON 约束：能否强制模型只输出合法 JSON？是平台参数（类似 response_format）还是只能靠提示词约束？
6. 图片输入：支持图片输入吗？能读出图里的文字吗？这条决定我们要不要做扫描件 OCR 加分项。
7. 文件输入：docx 或 pdf 能不能作为附件直接给你？还是必须先抽成纯文本贴进对话？
8. 并发与速率：并发调用和调用频率有什么限制？超了是排队还是直接拒绝？
9. 超时：单次请求多长时间会断？长输出会不会中途被掐断？
10. 采样参数：温度这类参数能调吗？在哪里调？
11. Credits：计费规则是什么，按 Token 还是按次？一次"输入约 8000 字报告全文 + 输出约 800 字 JSON"的调用大约消耗多少？我们总预算 2500，要撑到 9/26。

## 自检

交答案前过一遍：表格是不是 11 行一行不少；每个"已知"是不是都带了依据；全文有没有出现推测句式。三项里任何一项没做到，重写再交。
