# 三接口打通（桩版优先）

B 的前端已经实现完，在等后端能接。所以这份任务要**分两次交**：先交桩版让 B 立刻能关掉 Mock，再交真实现。

## 阶段一：桩版（最先交，做完立刻回传，不要攒着和真实现一起交）

FastAPI 起四个路由，响应体形状完全按契约，先用固定假数据：

- `POST /api/v1/reports` → 201，返回契约 7.2 的成功 JSON 原样，report_id 固定 `rpt-2001`。
- `POST /api/v1/reports/{report_id}/grading` → 202，返回契约 7.3 的成功 JSON。
- `GET /api/v1/reports/{report_id}/result` → 200，返回契约 7.4 里 status=success 的那段完整 JSON，四个新字段 student、comment、highlights、suggestions 都要出现并有值。
- `GET /api/v1/templates` → 200，从 `grading_templates` 读种子数据，支持分页。

所有桩响应加响应头 `X-Mock: true`，方便 B 一眼看出还在桩阶段。

交付内容：启动命令 + 上述四个 curl 的实际输出。这一步**不依赖**解析层和评分层，可以直接做。

## 阶段二：真实现

阶段一回传后接着做，按下面的优先级。三层（解析、评分、入库）若还没落地，先按上一份任务的要求把三层写出来，再接线，不要为了赶接口把逻辑塞进路由。

1. `POST /api/v1/reports`：multipart 收 `file` 与 `template_id`。校验与错误码：类型不是 docx / pdf → 4001（415）；超过 20MB → 4002（413）；空文件 → 4004（400）；template_id 不存在 → 4041（404）。算文件 SHA-256，落 reports 表，status=uploaded。幂等键冲突 → 409 + 4091，body 附已有 report_id。
2. `POST /api/v1/reports/{report_id}/grading`：report_id 不存在 → 404 + 4042；正在评阅中重复触发 → 202 返回当前状态且不重跑；已完成再触发 → 409 + 4091；正常 → 写状态机 parsing，把任务投进串行队列（并发 1），依次走 parsing → parsed → grading → 终态。
3. `GET /api/v1/reports/{report_id}/result`：返回状态机当前状态与完整结果。未出分时 items 为空数组，total_score 与 comment 为 null。
4. `GET /api/v1/templates`：真读种子数据，分页参数按契约。
5. `GET /api/v1/grades`：有余力再做。从 grading_results 读终态记录，支持分页、template_id 过滤、order 排序。

## 阶段三：冒烟脚本

`scripts/smoke.py`（或 .sh）：五步连跑——拉模板 → 上传一份 docx → 触发评阅 → 轮询到终态 → 拉成绩列表，每步打印返回码与关键字段，最后打印一行 PASS 或 FAIL。输出存档到 `docs/试跑记录_P2-07_冒烟.md`。

## 硬约束

- 字段名、错误码、HTTP 状态码一律以契约第 6、7 节为准，一个字符都不能差；响应体字段与契约的 JSON 示例逐个对。
- 上传与评阅是两步：上传只落库，不启动解析。
- 不引入 progress 字段，进度由前端按状态机换算。
- 结果接口必须带 student、comment、highlights、suggestions 四个字段。
- 全部中文文档与注释，不用 emoji。不许硬编码密钥。
- 单文件不超过 300 行，依赖只向下，路由层只做参数校验与编排。

## 自检

1. 桩版四个接口的响应体与契约 JSON 示例逐字段一致。
2. 真实现的四类上传校验错误码正确（4001 / 4002 / 4004 / 4041）。
3. 轮询能真实从 parsing 走到 success 或 partial_success。
4. 冒烟脚本一次跑通，最后输出 PASS。
5. 契约里五个接口的路径都已实现；若成绩列表后置，在回传里说明并把状态标出来。
6. 结果接口的四个新字段在桩版与真实现里都有值。

交稿时按阶段回传：阶段一的启动命令与 curl 输出先发一份，阶段二、三的气泡再发一份，每次都要带上当次的原始输出。
