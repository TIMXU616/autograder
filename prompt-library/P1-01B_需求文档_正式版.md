# 需求文档撰写任务

按下面的要求写一份需求文档。直接给正文，不要写"好的""以下是"这类开场，也不要在正文之外附加任何说明。

## 任务背景

比赛：粤港澳大湾区 AI Coding 创新大赛，方向一课题 2「AutoGrader」，实验报告智能评阅教学平台。
周期：2026/9/19 到 9/26，9/26 23:59 截止提交。
团队 3 人：A 负责产品、AI 管线、后端；B 负责前端 Vue3 + Element Plus；C 负责数据、测试、材料。
技术栈：FastAPI + SQLite 后端，python-docx 解析 Word 文档，pdfplumber 解析 PDF 文档，前后端分离。
主链路：教师选一套预置的评分点模板，上传一份实验报告（收 .docx 与 .pdf，单份不超过 20MB）→ 系统解析出全文 → 大模型按评分点逐项核查，给出每项得分、原文依据和评语 → 结果页展示，同时进成绩列表。
评委打分口径：技术创新 30%、工程完整性 25%、AI 工具使用深度 25%、用户体验 20%。

## 已拍板的三条前提（定死，不要再讨论）

1. 同时收 .docx 和 .pdf，这是团队确认过的口径。但只支持带文本层的 PDF：扫描版（图片型、无文本层）PDF 不做解析，系统检测到就返回明确的错误提示，不许崩。扫描件 OCR 解析属于加分档，不进必须档。
2. 评分点模板由教师预置、上传报告时选择绑定，AI 不生成评分点。
3. 无登录、单教师角色。前端没有登录页，接口不带鉴权，不做权限区分。

## 输出格式

Markdown，六个部分，顺序固定：

一、两类用户
二、核心流程
三、必须档
四、加分档
五、明确不做
六、完成判定

## 各部分的硬要求

一、两类用户：只写任课教师、助教两类。每类一句核心诉求，再配一个具体到场景的例子——什么时间、人在哪、要干什么。不要加第三类用户。

二、核心流程：不超过 5 步。每一步写清输入是什么、输出是什么、这一步归 A、B、C 里的谁。第一步从选模板开始，最后一步落在成绩列表。

三、必须档：只准 3 项——上传报告、AI 逐项评分、结果展示加成绩列表。每项写一句话说明做到什么程度算做完。

四、加分档：4 项候选——成绩导出 CSV、成绩统计图表、批量上传与批量评阅、扫描件（图片型 PDF）OCR 解析。按性价比从高到低排序，每项标注做它要花多少工作量、能换来哪条评分维度上的分。工作量用半天、一天、两天这种量级说，不要精确到小时。

五、明确不做：至少 5 条，每条必须写清不做的具体原因。这两条已定死，照写：登录与权限系统；多租户。其余你自己补齐。

六、完成判定：把第三部分和第四部分每一项列成一行，写一句怎么验证它做完了。判定要能让第三人独立看出做没做，不许出现"体验良好""运行稳定"这类说法。

## 文风

全文不超过 800 字，按中文字符数算，表格里的字也算在内。
禁止出现这些词：可能、大概、视情况、建议考虑、等等、诸如此类、一定程度上、赋能、一站式、闭环、抓手、显著提升、智能化。
禁止使用 emoji 和任何装饰性符号。
禁止用"首先/其次/最后"这类套话起句。
凡是该写具体数字的地方——超时、并发上限、Credits 消耗、报告长度上限——背景里没给的就写【待验证】，不要自己编一个数字。

## 自检

交稿前自己过一遍这四项：含糊表述是不是都删干净了；必须档是不是只有 3 项；不做清单是不是每条都带了原因；字数有没有超 800。四项里任何一项没做到，重写一遍再交。
