# 数据结构实验报告评分点模板 v1

你要产出两样东西：一份给人看的评分点表格，一份给程序用的 JSON。两样内容必须完全对应，字段一个不差。

## 第一步：先给一段参考摘要

先检索高校数据结构实验报告常用的评分标准（rubric）做法，用不超过 300 字总结三件事：常见的评分维度怎么划分、分值通常怎么分配、哪些做法能减少主观判断。不要列链接，不要抄原文，只给可用的结论。

## 第二步：产出模板

### 硬性结构要求

- 评分项 6 到 8 个，满分合计必须正好等于 100。
- 单项分值取 8 到 25 之间的整数。
- 必须覆盖这些维度：实验目的与原理、实验环境与步骤、算法与数据结构设计、代码实现、测试与结果、结果与分析、报告规范。可以合并或拆分，也可以另加一项（如扩展与反思），但不得缺项。
- item_id 从 1 起连号，不得跳号。
- 评分项名称不超过 12 个字，前端表格要显示。

### 每个评分项必须写全六项

1. 编号与名称。
2. 分值，整数。
3. 可观察判定标准：必须锚在能数、能看、能检索的东西上——字数、是否出现、出现几次、有无某个章节、代码段数量、图表数量、是否给出测试数据。禁止出现这些词：充分、深入、清晰、到位、较好、有一定、论述完整、思路清楚、严谨、完整度高。
4. 三档判定：优秀 / 合格 / 不达标，每档写清什么情况归这一档，并与下表对应。

| 档次 | 对应得分率 | 接口 level 取值 |
| --- | --- | --- |
| 优秀 | 0.90 及以上 | excellent |
| 良好 | 0.70 至 0.89 | good |
| 合格 | 0.50 至 0.69 | fair |
| 不达标 | 0.50 以下 | weak |
| 完全缺失 | 得分 0 | absent |

三档是本模板的判定口径，level 是接口返回的取值，两者按上表对应，不要在模板里另造一套分级。

5. 需提取的证据位置：写清该从报告哪一部分找证据（例如「第三章算法描述段」「第四章测试数据段」），以及证据的形态（一句连续原文 / 一段代码 / 一个数据表）。
6. 一条常见误判陷阱：写一个真实容易判错的情形，并说明正确判法。

### 附：评分项到判定问句的映射表

为每个评分项写一句判定问句。要求单句、可以回答是或否或给出数量、问句里包含证据位置。这张表后面要直接拼进评分提示词，必须能独立看懂。

示例：「报告是否在第三章给出了至少一段描述核心算法步骤的文字，且该段文字不少于 100 字？」

### 扣分护栏（必须写，每条都要给出可执行的处置动作）

1. 分项得分之和与总分不一致时怎么办。接口要求 total_score 必须等于各项 score 之和，处置动作要写清以谁为准。
2. 报告跑题（内容与数据结构实验无关）时怎么办。
3. 只有代码、没有正文说明时怎么办，写清哪些项能给分、哪些项必须判不达标。
4. 解析出来的正文过短（不足 200 字）时怎么办。
5. 模型给出的 evidence 在报告原文里找不到时怎么办。
6. 某个评分项模型调用失败时怎么办，对应接口的 5002 与 partial_success。

凡是涉及数值的处置动作，直接写具体值，不要写「视情况」。

## 交付物

文件一：`templates/grading/数据结构实验报告_评分点.md`

包含版本行（v1，日期 2026-09-21，适用课程 数据结构）、六字段表格、判定问句映射表、扣分护栏，末节写一段与 `docs/接口契约.md` 的对齐说明：item_id / name / max_score 三个字段的取值与类型必须与契约第 5.1 节 TemplateItem 完全一致；契约第 7.1 节示例里的 60 分三项目录属于示例数据，实际种子数据以本模板为准。

文件二：`templates/grading/数据结构实验报告.json`

结构如下，字段名一个都不能差：

```json
{
  "template_id": "tpl-1001",
  "name": "数据结构实验报告评分模板",
  "course": "数据结构",
  "total_score": 100,
  "items": [
    {
      "item_id": 1,
      "name": "",
      "max_score": 0,
      "criteria": "",
      "levels": {"excellent": "", "good": "", "fair": "", "weak": "", "absent": ""},
      "evidence_hint": "",
      "question": "",
      "pitfall": ""
    }
  ]
}
```

JSON 必须能被 `json.loads` 直接解析，不得有注释、省略号或尾随逗号。各评分项 max_score 之和必须等于 total_score。

## 自检

交稿前逐项过一遍：

1. 6 到 8 项，分值之和正好 100，编号不跳号。
2. 每条判定标准里有没有主观词，对照上面那份黑名单逐条查。
3. 随便挑一条，你能否仅凭它、不看任何背景，判出三档中属于哪一档。判不出来就重写这条。
4. 判定问句表是否每项都有一句，且问句里带了证据位置。
5. 扣分护栏六条是否齐全，每条是否给了具体处置动作和数值。
6. JSON 能否解析，是否与表格版逐项对应。

任何一项没过，重写再交。
