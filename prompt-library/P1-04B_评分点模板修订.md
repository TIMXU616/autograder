# 评分点模板修订任务（外科式修改）

这份模板已经过评审，只改下面指定的四处，其余内容一字不动。不要重写整份文件，不要顺手优化其他措辞，不要改动分值与判定问句。

## 前提

读取这两个文件：

- `templates/grading/数据结构实验报告_评分点.md`
- `templates/grading/数据结构实验报告.json`

## 改动一：给判定标准补上限与下限的关系

把 md 第三节开头那段「档位通用规则」整段替换为下面这段（一字不改地照抄）：

档位通用规则：每个评分项的判定标准由若干条可计数判据组成，判据命中几条决定落哪一档。判据是档位的下限锚点，不是分数的唯一来源——落档之后，档位内的具体得分由语义质量在区间内确定。例如命中 2 条判据落入 fair（得分率 0.50 至 0.69），内容确实讲对了取区间上端，讲得含糊取区间下端。判据全中但内容自相矛盾、明显编造的，下调一档并在 reason 里写明原因。与接口 level 的对应关系见下表。

同时在 JSON 顶层新增一个字段 `level_rule`，值为上面这段去掉开头六个字「档位通用规则：」之后的正文。

## 改动二：修正护栏第 5 条

把 md 第五节第 5 条整条替换为下面这条（一字不改地照抄）：

5. 模型给出的 evidence 在原文中找不到：该项 status 置 low_confidence、confidence 置 low、error_code 保持 null，保留原得分，warnings 追加「第 N 项依据未能在原文中定位」。不得因此判 failed，也不得使用 5003——5003 专指模型返回非法 JSON。若其余项至少一项 graded，整体 status = partial_success。

## 改动三：修正护栏第 2 条

把 md 第五节第 2 条整条替换为下面这条（一字不改地照抄）：

2. 报告跑题（内容与数据结构实验无关）：各评分项 score 置 0、level 置 absent、status 置 graded、confidence 置 high，reason 写明「报告内容与数据结构实验无关」；整体 status 保持 success，total_score = 0，warnings 追加「报告内容与数据结构实验无关，各项均 0 分」。注意：absent 是 level 取值，不是 status 取值。

## 改动四：把护栏搬进机器版

在 JSON 顶层新增一个字段 `guards`，值为字符串数组，元素就是修订后 md 第五节的六条护栏全文，一条一个元素，文字与 md 完全一致，顺序也一致。

新增的 `level_rule` 与 `guards` 只用于评分提示词拼接和文档对齐，不进入接口返回的 TemplateItem 摘要，这一点在 md 第六节的对齐说明里补一句。

## 连带处理：如果 scoring_v1.md 已经产出

如果 `backend/app/prompts/scoring_v1.md` 已经存在，在它的 user 模板里，除了已有的每个评分项的 criteria、levels、question、pitfall 之外，追加嵌入 JSON 的 `level_rule` 与 `guards` 两段内容，位置放在所有评分项之后、报告全文之前。

如果这个文件还没产出，那么在产出时把这两段带上。

除这两段之外，该文件的调用参数、输出字段约束、三版参数、超长策略、处置规则都不要动。
