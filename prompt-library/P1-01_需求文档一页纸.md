# P1-01 · 需求文档一页纸

> 2026-09-20 拍板更新：前提 1 原定只收 .docx，后经 C 提出、团队确认改为 **docx 与 pdf 双格式**（扫描版 PDF 仍不做、检测到报错，OCR 回加分档）。前提 2、3 维持。正式提示词见 `P1-01B_需求文档_正式版.md`，以该文件当前版本为准。

任务清单第 1 条。产物落在 `docs/需求文档.md`。
验收口径：B 读完能定页面范围，C 读完能定素材与测试用例，两人不需要回来追问字段。

用法（三步）：

1. 整段复制「提示词 A」发给 LearnBuddy，拿到 3 条关键假设。
2. 你自己拍板，把结论填进「提示词 B」里标了【待你填】的位置。
3. 整段复制「提示词 B」发出去。拿回正文后存成 `docs/需求文档.md`，再发群让 B、C 各提一条异议。

## 提示词 A（先让它把假设交代出来）

```
我们三个人在做一门课的实验报告评阅工具，准备拿去参加一个 AI Coding 比赛。下面是项目背景。

现在不要写正式文档。先列出你动笔之前必须确认的 3 条关键假设，每条按这个格式写：
- 假设是什么
- 如果这条假设不成立，文档的哪一部分要跟着改
- 你倾向取哪个值，理由

总字数不超过 400 字，不要客套，不要复述我给你的背景。

【项目背景】
比赛：粤港澳大湾区 AI Coding 创新大赛，方向一课题 2「AutoGrader」，实验报告智能评阅教学平台。
周期：2026/9/19 到 9/26，9/26 23:59 截止提交。
团队 3 人：A 负责产品、AI 管线、后端；B 负责前端 Vue3 + Element Plus；C 负责数据、测试、材料。
技术栈：FastAPI + SQLite 后端，python-docx 解析 docx，pdfplumber 解析 pdf，前后端分离。
主链路：教师上传一份实验报告（docx 或 pdf，单份不超过 20MB）→ 系统解析出全文 → 大模型按评分点逐项核查，给出每项得分、原文依据和评语 → 结果页展示，同时进成绩列表。
本次明确不做：登录与权限系统、多租户。
评委打分口径：技术创新 30%、工程完整性 25%、AI 工具使用深度 25%、用户体验 20%。
```

## 提示词 B（出正式版，把【待你填】补完再发）

```
按下面的要求写一份需求文档。直接给正文，不要写"好的""以下是"这类开场白，也不要在正文外面附加任何说明。

【项目背景】
比赛：粤港澳大湾区 AI Coding 创新大赛，方向一课题 2「AutoGrader」，实验报告智能评阅教学平台。
周期：2026/9/19 到 9/26，9/26 23:59 截止提交。
团队 3 人：A 负责产品、AI 管线、后端；B 负责前端 Vue3 + Element Plus；C 负责数据、测试、材料。
技术栈：FastAPI + SQLite 后端，python-docx 解析 docx，pdfplumber 解析 pdf，前后端分离。
主链路：教师上传一份实验报告（docx 或 pdf，单份不超过 20MB）→ 系统解析出全文 → 大模型按评分点逐项核查，给出每项得分、原文依据和评语 → 结果页展示，同时进成绩列表。
本次明确不做：登录与权限系统、多租户。
评委打分口径：技术创新 30%、工程完整性 25%、AI 工具使用深度 25%、用户体验 20%。

【已拍板的假设】
【待你填：把你在提示词 A 里拍定的 3 条结论原样抄进来，一条一行】

【输出格式】
Markdown，六个部分，顺序固定：
一、两类用户
二、核心流程
三、必须档
四、加分档
五、明确不做
六、完成判定

【各部分的硬要求】
一、两类用户：只写任课教师、助教两类。每类一句核心诉求，再配一个具体到场景的例子——什么时间、人在哪、要干什么。不要加第三类用户。

二、核心流程：不超过 5 步。每一步写清输入是什么、输出是什么、这一步归 A、B、C 里的谁。

三、必须档：只准 3 项——上传报告、AI 逐项评分、结果展示加成绩列表。每项写一句话说明做到什么程度算做完。

四、加分档：4 项候选，从这几个里挑——成绩导出 CSV、成绩统计图表、批量上传与批量评阅、扫描件（图片型 PDF）的 OCR 解析。按性价比从高到低排序，每项标注"做它要花多少工作量"和"它能换来哪条评分维度上的分"。工作量用半天、一天、两天这种量级说，不要精确到小时。

五、明确不做：至少 5 条，每条必须写清不做的具体原因。登录与权限系统、多租户这两条已经确定不做，其余你自己补齐。

六、完成判定：把第三部分和第四部分每一项列成一行，写一句"怎么验证它做完了"。判定要能让第三人独立看得出做没做，不许出现"体验良好""运行稳定"这类说法。

【文风】
全文不超过 800 字，按中文字符数算，表格里的字也算在内。
禁止出现这些词：可能、大概、视情况、建议考虑、等等、诸如此类、一定程度上、赋能、一站式、闭环、抓手、显著提升、智能化。
禁止使用 emoji 和任何装饰性符号。
禁止用"首先/其次/最后"这类套话起句。
凡是该写具体数字的地方——超时、并发上限、Credits 消耗、报告长度上限——背景里没给的就写【待验证】，不要自己编一个数字。

【自检】
写完自己过一遍这四项：含糊表述是不是都删干净了、必须档是不是只有 3 项、不做清单是不是每条都带了原因、字数有没有超 800。四项里任何一项没做到，重写一遍再给我。
```

## 拿回正文后你自己要做的两件事

一是逐句扫一遍含糊表述。重点查"支持""提供""优化"这类动词后面有没有跟可验证的东西，没有就改成具体动作。

二是发群收异议。用这句话，别问"有没有意见"：

> 需求文档 v1.0 在 `docs/需求文档.md`。B 你只看第三部分和第四部分，回我一条：哪个功能你现在定不了页面范围。C 你只看第二部分和第六部分，回我一条：哪个判定你现在写不出测试用例。今天晚饭前给我。
