## 一、背景

产品：AutoGrader，实验报告智能评阅教学平台。团队 3 人，9/26 23:59 截止提交。
架构：FastAPI + SQLite 后端，Vue3 + Element Plus 前端，前后端分离，无登录、单教师角色、无多租户。
主链路：选评分点模板 → 上传报告（docx / pdf，单份 ≤20MB，绑定模板）→ 后端解析全文 → 调大模型按评分点逐项核查 → 结果页展示 + 进成绩列表。
分工边界：上传只落库返回 report_id，不启动解析；「触发评阅」接口驱动 parsing → grading 全链；前端靠轮询「查询评阅结果」拿状态。

## 三、五组接口（方法与路径已定，字段你来填）

1. `GET /api/v1/templates`：评分点模板列表。返回模板 id、名称、适用课程、评分项摘要（item_id、name、max_score）、总分。
2. `POST /api/v1/reports`：上传报告。multipart/form-data，字段 `file` + `template_id`。成功 201，返回 report_id、初始状态、文件 SHA-256、上传时间。
3. `POST /api/v1/reports/{report_id}/grading`：触发评阅。成功 202。幂等规则：进行中重复触发返回 202 加当前状态、不重跑；已完成再触发返回 409 加业务码 4091，body 附 report_id。
4. `GET /api/v1/reports/{report_id}/result`：查询评阅结果。前端轮询用，返回状态机当前状态与（若已出）完整评阅结果。
5. `GET /api/v1/grades`：成绩列表。支持分页（page、page_size，默认 1/20）、按 template_id 过滤、按总分排序。只列出终态为 success / partial_success 的记录。

每组接口必须包含：请求字段表（字段名 / 类型 / 必填 / 约束 / 说明）、返回字段表、一个完整成功 JSON、至少两个不同错误码的失败 JSON。

## 四、状态机

uploaded → parsing → parsed → grading → success / partial_success / failed

每个状态写清：进入条件、谁触发（用户动作还是系统流转）、前端展示什么。三条附加规则：

- partial_success：部分评分项 status 为 failed / low_confidence / skipped，但至少一项 graded 出分。此时 HTTP 一律 200，靠业务 status 区分，禁止用 5xx 表达部分失败。
- failed：解析失败、模型整体失败、队列超时、全部评分项失败四种入口，分别对应哪些错误码，逐一写明。
- 状态只前进不回退；重新评阅（如后续做）属于新 attempt，不覆盖旧状态机。

## 五、评阅结果与 items 字段（一个都不能少）

评阅结果对象：`status`、`attempt_no`（从 1 起，模型层重试不递增）、`model`、`total_score`（可空）、`consistency`（可空；定义为同一报告两次完整评阅的 total_score 之差绝对值，仅在发生重新评阅时非空，未重评为 null）、`warnings`（数组，无警告时空数组，不是 null）。

items 数组每项：`item_id`、`name`、`max_score`、`score`（可空）、`level`（可空，取值与语义定义）、`evidence`（可空；非空时必须是报告原文的连续子串，禁止改写）、`reason`、`status`（graded / failed / low_confidence / skipped 四值）、`confidence`（high / medium / low）、`error_code`（可空，指向错误码表）。

## 六、错误码（12 个，全列）

4001 类型不支持、4002 超限、4003 无文本层、4004 空文件、4005 加密、5001 模型不可用、5002 超时、5003 非法 JSON、5004 Credits 不足、5005 排队超时、4041 模板不存在、4091 重复提交。

每个错误码一行表：业务码、HTTP 状态码、触发场景、前端提示文案方向。错误响应体统一结构：`{"code": 业务码, "message": "人类可读信息", "detail": 可选对象}`。

## 七、通用条款（单独成节）

- 幂等：上传幂等键 = 文件 SHA-256 + template_id；同键重复上传返回 409 加 4091，body 附已有 report_id。
- 并发与排队：并发评分上限 1（串行），超出的任务排队，等待超 120 秒置 failed 加 5005。
- 时间格式：ISO 8601 带 `+08:00` 时区。
- 字段命名：JSON 字段 snake_case；URL 路径全小写复数资源。
- 分页：page 从 1 起，返回体带 total。

## 八、验收标准

不少于 12 条 EARS 格式（When/If + 条件 + 系统必须 + 可观察行为），其中至少 5 条走异常路径。格式示例：

- If 上传文件大于 20MB，系统必须返回 HTTP 413，业务码 4002，message 说明大小上限。
- When 评分项全部 graded 且分项和等于 total_score，系统必须返回 status 为 success 的完整结果。

## 九、curl 端到端验证步骤

按顺序给出一组可直接复制执行的 curl：拉模板列表 → 上传一份 docx（-F 用法写全）→ 触发评阅 → 轮询结果（含 jq 取状态的写法）→ 拉成绩列表。每步标注预期返回码与预期 body 关键字段。
