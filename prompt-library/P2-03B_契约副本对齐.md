# 契约副本对齐（把你工作区的接口契约补齐）

`docs/接口契约.md` 现在有两份副本，内容已经分叉。仓库副本是权威版本（它同时挂着 `openapi.yaml`，B 生成类型和 C 写断言都以它为准）。你手上那份缺了三处，请按下面补齐，其余内容不要动。

## 改动一：错误码表 4001 那一行收窄

把你表里这一行：

| 4001 | 415 | 上传文件类型非 docx / pdf；或请求参数类型非法 | 「仅支持 docx / pdf 格式」 |

改成：

| 4001 | 415 | 上传文件类型非 docx / pdf | 「仅支持 docx / pdf 格式」 |

同时把 4002 那一行的触发场景改成：

| 4002 | 413 / 400 | 上传文件超过 20MB（413）；分页等参数超出上限或取值非法（400） | 「文件超过 20MB 上限」/「参数取值非法」 |

理由：4001 映射的是 HTTP 415，查询参数非法返回 415 是错的。7.1 与 7.5 里那两处参数类失败的示例，错误码由 4001 改成 4002。

## 改动二：通用条款补两条

在第四节「幂等」那一条后面插入两条：

- 上传与评阅分两步，本契约确认以此为准：上传只落库并返回 status=uploaded，不启动解析；由触发评阅接口驱动 parsing → grading 全链；前端轮询结果接口拿状态。
- 不引入 progress 字段。进度只有一个真值源，就是状态机；前端按状态机阶段换算进度条，建议映射 uploaded 10%、parsing 30%、parsed 50%、grading 80%、success 与 partial_success 100%。失败时进度条转错误态，不停留在中途百分比。

## 改动三：两处字段定义对齐

1. GradingResult 里的 student 一行，改成：

| student | string \| null | 提交人显示名。后端取上传文件名去掉扩展名作为初值；未取到为 null。模型不输出该字段 |

（原写法没标可空，实际可能取不到，必须标 null。）

2. GradeListItem 补一行 student，位置放在 filename 之后：

| student | string \| null | 提交人显示名，与结果接口同源 |

同时把 7.5 成绩列表的成功 JSON 示例里两个列表项各加一个 `"student"`，值分别用「单链表实验报告」与「图遍历实验报告」。
